# Моя учёба

Личный органайзер дисциплин и занятий по двум согласованным макетам.

## Возможности

- Создание, поиск, переименование и удаление дисциплин; выбор цвета и значка.
- Ссылки на урок, курс, материалы и дополнительные ресурсы.
- Недельное и месячное расписание, фильтр по дисциплине, переход к текущей дате.
- Разовые и еженедельные занятия, произвольное время начала и окончания.
- Быстрый переход из занятия к его ссылке или дисциплине.
- Проверка данных, подтверждение удаления, состояния загрузки и ошибок.
- Сохранение в Cloudflare D1. LocalStorage не используется для учебных данных.

Первое открытие создаёт шесть редактируемых примеров дисциплин и расписание текущей недели. Адреса ресурсов изначально пустые: пользователь добавляет свои ссылки. Удаление дисциплины удаляет её ресурсы и занятия. Изменение повторяющегося занятия применяется ко всей серии.

## Структура

- `app/study-app.tsx` — дисциплины, навигация, ссылки, состояние приложения.
- `app/study-calendar.tsx` — оба представления календаря.
- `app/study-forms.tsx` — формы дисциплин, ссылок и занятий.
- `app/api/study/route.ts` — серверные запросы, валидация, первоначальные примеры.
- `db/schema.ts` и `drizzle/` — схема данных и миграции.
- `app/globals.css` — оформление по макетам и адаптация экранов.

## Разработка

Требуется Node.js 22.13+ и pnpm версии, указанной в `package.json`.

1. Установить зависимости: `pnpm install --frozen-lockfile`.
2. Собрать проект: `pnpm build`.
3. Применить локальную миграцию:
   `node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_simple_satana.sql`.
4. Запустить локальную разработку: `pnpm dev`.

При работе внутри Sites используются стандартные команды его навыка для установки, сборки и предпросмотра. Миграции рабочего сайта применяются при публикации. Локальная тестовая база в рабочий сайт не переносится.

Сайт опубликован с доступом только владельцу. Данные принадлежат одному личному пространству. Перед изменением доступа на публичный потребуется добавить разграничение данных по пользователям.

## Проверка

Проверены сборка, типы TypeScript и браузерные сценарии: создание дисциплины, сохранение ссылки и сохранность после перезагрузки, поиск, редактирование времени занятия, отклонение неверного времени, еженедельное повторение, месячное представление, подтверждение удаления. Временные тестовые записи удалены из локальной базы.

Встроенные WebMCP-действия включаются только в поддерживающем браузере. Проверка через WebMCP в текущем браузере недоступна: `document.modelContext` не предоставлен. Обычный интерфейс работает независимо от этой возможности.
